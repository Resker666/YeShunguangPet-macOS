# D：资源基线与午夜通知崩溃调查

日期：2026-10-22晚至23日凌晨（Asia/Shanghai）。D调查的四组主采样与日用参考已完成；额外待机复测在真实午夜崩溃时中断，生产App也发生同一崩溃。已实施有界修复，0.1.21本地交付待最后核验。

## 方法与口径

Mac mini M4（Mac16,10），10逻辑CPU、16 GiB，macOS27.0/build26A428；Xcode27.0/build27A266a、Swift6.4。角色backingScale1，可用区域1920×977逻辑点。个人App同时运行，宿主自然使用状态及系统负载未经控制。

测量源码`a90c5e18dfed8c2bdba2bfa357ef8de287291de7`，运行代码与已交付`e15b739`相同。临时包装程序以`-O`/whole-module优化编译，直接复用未修改的AppDelegate、StatusBarController、PetSession和FocusController，独立Bundle ID及配置/Skins。它是**同源优化探针，不是字节相同的正式App**。编译命令、生产Swift/素材及二进制哈希保留在本机证据中。

四组串行，每组预热30秒后采样600秒，外部每5秒核对准确可执行路径、PID启动时间并读取CPU累计时间/RSS；每组121个样本，均正常退出。固定随附叶瞬光、100%大小、置顶、注视开启，自动动作/走动/台词/提示音关闭，25/5分钟，200×112紧凑计时窗。隐藏组同时隐藏两窗且**计时未运行**；专注组启动25分钟段，在完成前结束测量。

CPU=累计CPU时间差÷单调时间差×100，100%代表一核。`ps`累计CPU时间有量化，约5秒区间峰值不是瞬时峰值。RSS包含共享驻留页，不等于独占物理内存。首尾变化取各12个样本（约一分钟）的中位数差，不能据此断言泄漏。

## 实际发现与修复范围

00:00:00的探针与00:00:05的日用App均SIGTRAP，后台堆栈为`__postAndResetMidnight`→`@objc FocusController.calendarChanged`→Swift6 MainActor隔离断言。原代码用隔离selector接收Foundation默认通知，真实投递可在后台；此前测试仅在主Actor发通知，未覆盖该路径。

0.1.21/build22只修复日期、时钟、时区共用入口：selector非隔离；主线程保持同步刷新，后台转至MainActor；排队任务遇dispose后忽略。schema13、统计归属、手动衔接、计时及调度频率不变。无相同故障证据的AppKit/NSWorkspace通知保持原实现。[补丁计划](superpowers/plans/2026-10-23-macos-calendar-notification-crash.md)。

新增回归先在旧实现重现同一SIGTRAP（xcodebuild65）；修复后完整336项原生（130Core＋206Mac）和13项离线发版通过。覆盖三种后台通知刷新今日/菜单、主线程回调、保留旧日汇总、无额外写盘/计时器、排队后dispose忽略；既有主线程同步通知回归继续通过。独立优化编译同源探针连续后台投递300次通知，300次主线程回调、通知期间配置字节不变、准备态无Focus计时器及正常退出均通过；它仍不等于正式二进制跨过真实午夜。单一最终评审、干净包和本地替换结果待补。

本轮未测系统/GPU功耗、电池、过夜耐久、其他皮肤/缩放/Retina或Intel/Sonoma资源；旧版数据不代表0.1.21性能改善。修复后下一次真实午夜尚待日用观察，不改系统日期冒充实测。

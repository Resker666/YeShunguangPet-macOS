# 0.1.12：手动检查更新、全局快捷键与设置分组

日期：2026-10-21（Asia/Shanghai）。

状态：用户已选择A、B、C，并在阅读本设计后回复“执行”，设计已批准；尚未开始产品代码实现或配置迁移。之后沿用用户已选择的本会话实施方式，在独立Mac仓库原地开发，先本地交付；本版推送、标签、Release草稿和公开发布均另等明确指令。

## 目标与范围

面向用户自己的Mac mini M4日用，并改善其他人安装后的使用体验：从App查询公开新版、通过三个全局组合键操作角色，以及按用途查找设置。沿用Swift 6、AppKit、SwiftUI、macOS 15+和现有双架构分发，不新增第三方运行库、登录服务或收费签名依赖。

本轮A/B/C的含义固定如下，沿用现有菜单和皮肤行为：

| 项目 | 首轮交付 |
| --- | --- |
| A 手动检查更新 | 菜单与“关于”页提供入口，显示当前/公开版本、说明、发布页和对应CPU架构的DMG下载入口 |
| B 全局快捷键 | 显示/隐藏、召回、切换安静模式；可设置、清除并保存组合键，提示本App重复与系统登记冲突 |
| C 设置分组 | 皮肤、通用、互动、快捷键、关于五组；保留皮肤选择/拖入/预览/确认/删除和既有偏好功能 |

本轮不替用户自动安装新版、不增加后台定期检查，不改皮肤JSON/PNG，不实施尚待手动验收的睡眠/Spaces/登录行为调整。Windows和Minimal Sleep继续只读。

## 已检查的工程事实

基线main为`fa64742a969fdcb8c1a7c433fb0d25cbce268efd`，工作区干净。0.1.11已获本机整体体验通过并推送；main云端39561818426与开发分支39561818484成功，187项原生、13项发版离线、10项分发回归通过，普通push的release-draft job确认为skipped。公开Release在本次检查时仍为v0.1.9；这不是0.1.12开始后的固定假设，运行时应实际查询。

`StatusBarController`已有三个角色命令及设置入口，`SettingsWindowController`拥有原生拖放入口和共享预览任务。`PetSession`主线程管理运行状态和偏好，`SettingsStore`保存schema7并读取1–7；旧配置损坏/未知版本时保护原文件。现有普通偏好即时生效后再尝试保存，这次快捷键还需要独立处理系统登记与落盘的协调，不能直接假定两者原子成功。

本机公开SDK的`HIToolbox/CarbonEvents.h`仍提供RegisterEventHotKey、UnregisterEventHotKey及kEventHotKeyExclusive。这些API不是线程安全的，统一在主线程管理。SDK明确：非独占登记可以被多个App同时使用，独占冲突由系统返回状态；因此采用独占登记，并且不承诺能发现所有应用内的局部快捷键。

## 设计选择与主要取舍

选择系统URLSession和原生快捷键登记，继续由现有菜单/设置编排。相比引入更新框架、第三方快捷键库，首轮依赖更少，代价是需要自行测试有界响应、登记回滚和退出释放。

快捷键界面采用“修饰键勾选 + 按键选择 + 应用/清除”，首轮不增加全局按键监听或录制器。这样仍可修改组合键，并使编辑时已有全局绑定、Esc取消、焦点变化等录制器状态不进入本轮。按键集合限定常用字母、数字与F1–F12，美式物理键位清楚标注。以后如有实际需求再增加录制方式。

设置采用固定分组而不是新增多窗口。显示、安静等动作继续调用PetSession既有方法，只有输入来源增加。更新客户端、系统快捷键适配与纯数据校验分离，不把网络状态放入角色动画调度。

## A：手动检查更新

### 用户流程

1. 在菜单点击“检查更新…”时打开设置的“关于”页，并开始一次查询；页内按钮可手动重试。
2. 展示当前版本及查询状态。成功后显示公开版本、更新说明摘要、发布页和本机架构DMG入口。
3. 分别显示有新版、版本相同、当前开发版高于公开版。尤其是当前开发0.1.12而公开0.1.9时，不能提示可降级更新，也不能称两者版本相同。
4. 点击发布页或下载按钮才交给系统浏览器打开。缺少对应架构附件时保留发布页入口，明确该架构安装包尚不可用。

### 请求和数据边界

- 只有上述用户操作发起请求；启动、打开普通设置、菜单刷新、唤醒、角色互动均不查询。
- 固定GET `https://api.github.com/repos/Resker666/YeShunguangPet-macOS/releases/latest`，匿名访问公开数据，使用GitHub官方API头；不读取个人Token或Git配置。
- 使用临时URLSession，禁用持久缓存和Cookie；不发送个人配置、皮肤、位置、快捷键或其他应用内容。
- 请求超时15秒、资源总超时20秒；响应体最多1 MiB，既检查声明长度，也限制实际接收字节。只接受HTTPS预定API目的地，禁止重定向到其他来源。
- 版本只接受本仓库的稳定三段数字标签，可有前缀v；各段有数值范围检查，按数值比较，避免0.1.10被当成低于0.1.9。
- 解析公开非draft、非prerelease的Release。只提供本仓库HTTPS发布页，以及名称/路径均与所解析版本、CPU架构对应的官方Release附件链接；拒绝外站、带凭据或不匹配的URL。
- 说明作为纯文本摘要展示，最多约8000字符，完整内容通过发布页查看；不执行HTML或远端脚本。
- HTTP错误、限流、无公开版本、超时、断网、损坏/超大响应分别提供可重试提示，不影响角色、个人设置或皮肤库。
- 并发点击复用同一请求；关闭设置或退出时取消。结果带请求代次，取消后的旧响应不能覆盖重新打开后的状态。单独的更新状态不占用皮肤的isBusy/hasPendingMutation。

## B：全局快捷键

### 默认和界面

三个动作默认均不绑定，不抢占用户现有组合键。用户在“快捷键”组分别编辑修饰键与按键，点击“应用”才登记和保存；“清除”解除该动作。切页或关窗丢弃未应用的编辑，不改变已应用绑定。

首轮组合键至少包含两个修饰键，且至少包含Control或Option；使用限定的常用字母/数字/F1–F12物理键集合。校验无效输入、同App重复、系统拒绝登记时给出具体动作及原因。系统冲突提示只对应真实登记结果，不声称能枚举其他应用的全部快捷键。

### 登记与命令

- 使用公开Carbon全局快捷键API和kEventHotKeyExclusive；登记、取消、状态更新统一在主线程，正常退出显式释放事件处理器与登记。
- 系统适配只负责登记指定组合键并接收相应热键事件，不采集其他应用键盘输入。
- 三个动作直接复用显示/隐藏、召回和安静模式；不另建角色状态或绕开既有输入取消/保存规则。隐藏时仍能通过快捷键找回角色。
- 菜单展开、设置有模态sheet、退出期间不执行热键动作；普通设置打开时可用。按下/松开成对跟踪，同一次按住不会反复切换状态；旧登记、取消及退出后的排队事件忽略。
- 事件回调安全转到主线程，处理器的上下文在系统撤销后才释放，不能留下悬空指针或应用退出后的回调。

### 保存及失败恢复

快捷键的候选登记、旧登记释放、配置落盘作为一个受控操作编排。本App重复或新组合键被系统拒绝时，不改旧登记或配置。保存失败时撤销候选并恢复旧登记；必须检查系统恢复结果。如果恢复本身失败，显示真实已登记/未登记状态及重试入口，不声称恢复成功，也不把失败候选保存为用户偏好。

启动在PetSession加载配置完成后登记已保存组合键。某个组合键已被其他进程占用时，保留用户设置并显示该动作未激活，其余成功绑定继续可用，允许重试/更改。不得在每次菜单刷新或逐帧重新登记。配置受保护时不允许绑定变更写盘；重置配置、清除绑定、退出都要同步实际系统状态。

## C：设置页分组

| 分组 | 内容 |
| --- | --- |
| 皮肤 | 当前角色、选择/恢复默认、待导入预览、已导入库及刷新/删除 |
| 通用 | 大小、置顶、系统登录启动和真实系统状态 |
| 互动 | 注视、自动小动作、走动、台词及相关间隔 |
| 快捷键 | 三个动作的组合键编辑、应用/清除、登记及保存结果 |
| 关于 | 当前版本/架构、手动检查更新、版本和下载结果 |

使用SwiftUI TabView，窗口继续为普通可取焦点的设置窗口。每组可独立滚动，保存失败提示在各组可见。首次打开默认皮肤，普通重开保留本次会话选中的分组，分组本身不写配置。

0.1.11已经支持将文件拖入整个设置窗口，本轮保留这个行为：从任意分组拖入单个支持的本地文件，会转到皮肤组并进入共享预览确认。切组不导入、不中断有效预览；关闭设置仍取消未确认操作。文件选择/删除确认sheet和处理状态继续阻止冲突的拖入。原有登录项只在用户操作时登记/撤销，不因拆页重建而重复调用。

## 配置兼容与组件边界

配置升级schema8；读取schema1–7时沿用原迁移，新增快捷键默认为空，完整保留原位置、皮肤UUID、台词、缩放、置顶、注视及自动动作/走动开关与间隔。有效v7缺少新增字段是正常旧配置；v8缺字段、类型错误、未知动作、越界键码/修饰键或重复组合键则保护原文件。保存仍受64 KiB限制且原子替换。更新查询及选中分组不加入配置。

| 组件 | 责任与依赖 |
| --- | --- |
| PetCore更新模型 | 版本比较、Release数据/可信链接校验，不发网络请求 |
| PetCore快捷键模型 | 动作、按键/修饰键、重复与有效性校验，参与配置编码 |
| SettingsStore | v1–7迁移及严格v8读取/保存，继续保护坏文件 |
| ReleaseUpdateClient / 更新状态 | URLSession请求、有界读取、取消与状态展示，传输可替换用于测试 |
| 系统HotKey适配 / ShortcutController | Carbon登记生命周期、冲突、事务协调和命令路由，登记器可替换用于失败测试 |
| PetSession | 继续拥有偏好和角色运行；提供不会在失败时假装已保存的快捷键变更边界 |
| StatusBarController / AppDelegate | 菜单入口、服务持有、配置加载后登记与退出释放 |
| SettingsWindowController及分组视图 | 复用共享皮肤模型/任务，显示更新与快捷键状态，不承担网络解析或Carbon回调 |

不为纯转发增加协议；只在外部网络、系统登记和磁盘失败确需替换的位置保留边界。新增源文件登记到相应App/Core/Test目标，继续只维护一份生产源码。

2. 快捷键覆盖默认空、有效/无效/重复、系统冲突、保存失败恢复、恢复失败真实状态、启动冲突、清除、退出释放、重复按下和过期事件；用登记器边界替身保留真实控制器/配置决策。
3. 配置覆盖1–7迁移保留及v8往返/损坏保护，测试配置与素材目录始终隔离。
4. 原生整合覆盖菜单路由、五分组、任意组拖入转皮肤预览、切组/关闭/模态sheet、已有导入事务及登录项刷新，不把模拟输入当成真实全局按键。
5. 在独立测试Bundle/配置中做一次真实匿名更新GET，按实际公开版本记录结果；用公开API实际登记/撤销测试组合键并验证独占冲突。不会修改正式个人快捷键或正式登录项来冒充测试。
6. 查看各组渲染，尤其皮肤预览、长错误/更新说明和快捷键编辑；真实跨应用按键、Finder拖放和焦点仍按实际操作单独记录。
7. 完整原生、发版离线、双架构构建及分发回归通过；独立只读评审后修复问题，再生成来源干净的ARM/Intel DMG/ZIP和校验文件，核对签名/内容/原始素材以及ARM搬移重开。
8. 本机日用App更新前备份并准确退出旧进程，核对schema7→8保留原偏好/皮肤/位置，默认快捷键为空，不主动检查更新或修改登录项。交付本地arm64 App和体验步骤；外机、Intel、真实睡眠/Spaces及云端执行未测项照实保留。

## 主要风险

- 网络限流/断网、Latest指向较旧版本或缺某架构附件：状态分别处理，保留可信发布页，不阻塞桌宠。
- Carbon属于较早的公开接口且非线程安全：仅使用当前SDK公开声明、主线程管理并做实际登记/冲突检查；真实跨应用触发不能由API成功推定。
- 系统登记与文件保存跨两个资源，无法靠一次磁盘原子写入保证全部成功：测试失败/恢复路径，恢复失败展示真实状态，不隐藏部分成功。
- schema8与设置拆页可能破坏旧偏好、导入退出协调或登录项刷新：以迁移、原有回归和分组整合检查验证，不改原素材和既有个人配置。

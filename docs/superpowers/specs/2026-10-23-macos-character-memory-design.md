# 角色长期记忆首版设计

日期：2026-10-23（Asia/Shanghai）。基线：`2c15595bcf2b3795b2101b1771b8f21139f4ec88`（0.2.0/build24，main 与原开发分支已推送且两路 CI 通过）。

状态：用户选择 A「角色长期记忆」，随后选择「从对话提炼候选：模型整理可能值得记住的内容，你确认后保存」。用户已于2026-10-23明确「认可书面设计，进入实施计划」，并选择直接审阅文字、不先看界面草图；对应计划为 `../plans/2026-10-23-macos-character-memory.md`，用户随后已认可该计划、授权本会话连续实施。沿用独立 Mac 仓库、本会话原地实施与一次最终独立代码评审；只建立本地 `codex/macos-character-memory`，不另建工作树。推送、标签、草稿及 Release 仍需新的明确指令。

## 1. 目标和首版范围

现有聊天仅将已应用的人设、最近 12 轮完整问答及本次输入提供给 DeepSeek。较早的信息离开上下文后，角色无法持续参考它。用户希望角色能记住已经确认的称呼、喜好和约定，同时能查看、纠正和删除记忆。

本轮选用模型提炼、人工确认的方式。以下触发时机、容量、候选寿命、版本号与界面组织是作者提出的实现选择，供本次审核，并非此前用户已经逐项确认的要求。

建议交付版本为 **0.3.0 / build25**：在 0.2.0 文字聊天基础上增加可管理的长期记忆能力。成功标准：

1. 用户点击「提炼记忆」，从当前角色已经保存的最近 12 轮完整对话产生至多 5 条候选；显示依据，允许修改、勾选，再明确保存。
2. 未确认的候选不会进入持久档案或普通聊天上下文。拒绝、停止或失败不会自动再请求。
3. 每个 `manifest.id` 最多保存 20 条、每条最多 200 个 UTF-16 单元的记忆。可修改、单条删除或确认后全部清除；满额时由用户整理，不自动淘汰、合并或覆盖。
4. 已保存记忆随此角色后续的普通聊天请求发送，不受最近 12 轮裁剪影响，重开仍可用；不同角色 ID 隔离，同 ID 皮肤副本共用。
5. 原有 v1 聊天档案无损读取为「记忆为空」，后续明确保存时写入 v2；主配置保持 schema13，原人设、历史、皮肤、快捷键、位置、专注及其持久偏好保留。
6. 完成有依据的回归、一次最终独立评审和双架构打包，交付本地可体验的 arm64 App。Intel 交叉构建不写作 Intel/Sonoma 实机通过。

首版围绕显式按钮提炼；自动按轮数提炼、模型直接写记忆、跨角色共享个人档案、无限聊天日志、向量检索、后台同步、语音和系统操作均留待后续需求。未保存的旧对话无法恢复，提炼不能回溯已经裁掉的轮次。

## 2. 方案及已作选择

| 方案 | 收益与代价 | 本轮决定 |
| --- | --- | --- |
| 手动输入或从对话复制记忆 | 无额外 API 请求，内容最可控；整理主要靠用户 | 已提供，用户选择下面的模型候选方案 |
| 模型整理候选，用户确认后保存 | 减少手工整理；需额外请求、候选核对和失败处理 | 用户明确选择 |
| 模型自动维护全部长期记忆 | 日常操作少；错误事实、覆盖及自动请求难以控制 | 与本轮确认后保存的范围不符，不采用 |

作者建议采用手动按钮触发，每次一个请求，继续使用当前连接页选定的 DeepSeek 模型和已配置钥匙串项。模型候选只是资料，不能触发工具、设置或记忆变更。

基础约束保持 Swift 6、AppKit、macOS14+、系统框架和现有 Xcode。窗口继续使用现有原生聊天窗口；不增加外部 SDK，不改 Windows 仓库、Minimal Sleep 或真实旧皮肤字节。

## 3. 使用流程

### 3.1 记忆管理

聊天窗口增加「记忆」入口，仍是同一窗口；现有「对话 / 人设 / 连接」功能继续保留。记忆页提供条目数量、已保存列表、单条编辑/删除、全部清除和「提炼记忆」。实际控件排布由实施阶段根据最小窗口原生渲染决定，不扩展主设置窗口的七个 Tab。

无记忆时说明角色目前只有最近 12 轮上下文。普通聊天发送的是已保存记忆；未保存的编辑和候选不会发送。每条编辑明确点击保存才生效，单条删除及全部清除均需确认。列表为纯文字，不运行链接或模型指令。该页可在 AI 关闭、无密钥或断网时管理已有本地记忆。

只有当前角色至少有一轮已保存完整问答，连接有效且没有正在进行的 AI 请求、角色写入、完整未保存问答、受保护资料、模态、睡眠或退出阻挡时，才允许提炼。提炼只读取当前档案；不含正在输入的草稿、半条回复、未保存的完整问答或其他角色资料。满 20 条时提示先删除或整理记忆，再提炼。

### 3.2 提炼和确认

点击按钮即明确发起一次额外 API 请求，按钮附近说明计费和发送范围。提炼期间显示状态并提供停止，不逐段显示 JSON。普通聊天、人设/记忆修改、模型与密钥变更暂停，关闭 AI 始终能立即取消；不修改对话输入草稿，不把提炼指令或结果记入普通聊天，也不触发桌宠挥手/气泡。

正常结束并完整解析后，一次显示 0–5 条候选。每条带可展开的来源：提炼快照中的轮次与对应用户原话，由 App 从本地快照取出，模型不能伪造来源文字。原话只在本地候选确认中显示，不写入诊断或 Git。

候选初始不勾选。用户可修改文字，勾选需要保存的条目，再点击「保存所选」。不选中任何项不能保存；「丢弃候选」只丢弃临时结果，不影响已有记忆。没有候选时显示「本次没有可新增的记忆」，不是网络错误；重新提炼始终需要用户再点一次。

模型请求要求只提取有用户表达或明确认可依据的稳定称呼、喜好、事实或约定；助手自行创作的角色背景、推测和临时角色扮演不应转成用户事实。来源核对只能保证引用来自当前快照，不能证明模型语义正确；最终文字由用户确认。

同一份临时候选可跨页面保留。候选是运行内的草稿：关闭窗口、成功换肤（含同 ID 副本）、成功清空历史/重置角色资料、开始退出会丢弃尚未确认的候选与编辑；页内提示该规则。最小化、隐藏 App、仅隐藏桌宠不会丢弃。睡眠或关闭 AI 取消正在提炼的请求；已经完成的候选可继续本地确认。停止只停止请求，不能承诺撤回服务商已收到的内容。

已有候选时可以继续普通聊天。候选依据仍是当时冻结的对话快照，页面说明这一点；新问答不悄悄改变候选或来源。再次提炼前明确丢弃旧候选，避免误覆盖未确认编辑。成功修改/删除已保存记忆或应用新人设也丢弃旧候选，防止它们沿用过时的提炼条件。

## 4. 记忆模型与普通聊天

每条已确认记忆含由 App 分配的 UUID 和正文。记忆条目不携带可执行操作；模型不提供条目 ID，也不指定需要覆盖的已有条目。保持用户保存的顺序，新条目加在末尾。正文先规范为 Unicode NFC、去除首尾空白，再按现有 `ChatText` 规则校验：非空、多行纯文字、最多 200 UTF-16 单元，拒绝非法控制字符。同一角色不接受规范化后完全相同的正文；不做语义相似度判断或自动纠错。

每个角色另有持久 `memoryRevision`，初始 0，每次记忆列表成功变更递增。20 条上限意味着正文合计至多 4000 UTF-16 单元；不增加无限累积或自动摘要。

普通发送冻结人设、已保存记忆及其修订号、最近 12 轮和当前输入。系统提示中有明确的「用户已确认的长期记忆」资料区；要求当次用户明确纠正与旧记忆不一致时依据当前表达回应，但模型不能自行改写磁盘记忆。说明模型实际能看到的范围，继续禁止声称读到未提供的屏幕或文件。空记忆角色保持原行为。

删除记忆后，后续请求不再通过长期记忆区发送它；若最近 12 轮或人设仍包含同样文字，模型仍可能看到。页面帮助解释这一范围，不声称删除 DeepSeek 已接收的数据。清空普通聊天历史保留人设和已确认记忆；单独清除记忆保留人设和历史。受保护角色档案的「备份并重置」重置整份角色资料，确认文案明确包括人设、历史和记忆。

## 5. 提炼请求与解析

本次于 2026-10-23 核对 [DeepSeek JSON Output](https://api-docs.deepseek.com/zh-cn/guides/json_mode/) 与 [Chat Completions](https://api-docs.deepseek.com/zh-cn/api/create-chat-completion/)：JSON 模式使用 `response_format: {"type":"json_object"}`，提示中需明确 JSON 和样例；官方也说明可能出现空 content 或长度截断。不能把文档支持写作用户账户已经完成真实提炼验证。

拟复用现有固定官方端点、无 Cookie/缓存、拒绝重定向和 SSE 完成验证的传输，区分普通聊天与提炼的类型化快照。提炼使用非思考、`stream:true`、`max_tokens:2048` 和 JSON 输出选项；收齐正常 `stop` + `[DONE]` 后才解释 JSON，候选不流式发布。不因 JSON 模式或解析失败自动退回另一请求。

请求仅含固定提炼规则、带明确轮次索引的当前角色已保存问答，以及该角色的已确认记忆用于避重。不提供角色自定义人设作为提炼指令，不提供未发送草稿、其他角色、文件、工具或屏幕内容。用户和助手原文以结构化资料提供，固定规则要求将其中的命令也视为对话资料。

返回格式：

```json
{"candidates":[{"text":"用户希望被称为小林。","sourceRounds":[1]}]}
```

`sourceRounds` 是提炼快照内从 1 起的完整轮次，每条至少引用一个存在的用户消息，去重后最多 12 个。正文最多 200 UTF-16，原始候选最多 5 条；不接受额外的修改/删除指令。解析前验证严格 JSON、重复键和容量，验证确切字段/类型、来源范围、非空文字和上限；未知字段或任一无效候选使整批失败，不部分采纳。允许合法空数组。

收到候选后按同一正文规范化规则去除与已有记忆及批内完全重复的项，并告知去重结果；用户编辑后的重复项在确认时明确拒绝并保留编辑，不静默改动选择。满额或所选数量超出剩余位置时要求先取消部分选择或整理已有记忆，不截断保存。

保留既有 1 MiB 请求/总响应、30 秒请求闲置和 120 秒总时限、64 KiB 单 SSE 行/事件及 8000 UTF-16 文本累计界限；收齐后的 JSON content 另限制 16 KiB UTF-8。HTTP、空/截断结果、工具调用、非正常结束、解析错误或超限均用本地说明，原记忆不变。没有自动重试、备用模型或额外总结请求。错误日志不包含密钥、正文、来源或原始响应。

## 6. 档案升级与保存事务

沿用 `AI/characters/<角色ID的SHA-256>.json`，不建另一套主配置或改变钥匙串标识。角色档案 v2 维持顶层 `{schemaVersion:2, conversation:{…}}`；conversation 保留 characterID/profile/messages，增加 memories（条目 id/text）与 memoryRevision。仍受 2 MiB 文件上限、身份和完整 12 轮校验约束。修订为非负 UInt64，溢出时拒绝变更而非回绕；备份并重置形成新空档案，修订回到 0。

以显式旧结构读取 v1，映射到空记忆/修订号 0，保留 ID、人设及每条历史。单纯读取不重写文件；首次明确的人设、完整问答、历史清空或记忆保存才写 v2。v2 必须具有合法记忆与修订字段；不得用宽松默认掩盖损坏。未知版本、重复键、非法 ID/正文/修订或数量进入原文件保护，不覆盖。旧版 App 遇到 v2 会按未知版本保护，而非读后丢记忆重写；说明回退旧版的这一限制。

继续使用原 0700 目录、0600 文件、同目录临时文件原子替换与先备份再重置。原子替换不等于断电耐久承诺。

记忆增删改/全部清除进入现有 FIFO 写入队列，由 worker 对最新角色档案操作，保留最新人设与历史。提交捕获目标角色、原 memoryRevision 和用户确认后的完整列表；worker 重新验证修订、容量、重复与文本，再落盘并推进修订号。修订不匹配明确失败，不覆盖后来状态。应用人设、追加问答/裁剪及清空历史均须保留记忆和其修订号。

候选确认必须在主线程重新核验当前完整角色上下文（含 skinRevision）、候选批次、记忆修订和可变更状态。删除确认等 sheet 结束、现有模态门控解除后，再登记事务；不能在 sheet 内绕过 `canDispatch`。已登记的事务不因关闭窗口、换肤、睡眠、关闭 AI 或网络取消撤回，仍保存到确认时的角色。完成回执按角色及事务序号更新缓存，不能把旧结果发到另一个角色或恢复已丢弃的候选。

成功后新列表才成为后续请求的有效记忆，候选/编辑相应清除。保存失败保留旧有效列表及用户确认的精确变更意图，按角色保存在运行内；提供「重试本地保存」和「放弃本次变更」。重试不提炼、不访问 API；未处理前暂停该角色的发送、提炼及其他资料修改，其他角色可继续。失败意图跨关窗/换角色保留，与尚未确认草稿的寿命不同。

正常退出先取消请求、等待已接受写入，再汇总所有角色的未保存完整问答、记忆变更和连接保存问题，沿用重试本地保存、明确继续退出、取消退出。未确认候选/编辑不自动保存，不新增退出义务；已确认但失败的变更参与现有退出失败处理。取消退出不自动恢复网络请求。

## 7. 请求与生命周期协调

App 内任一时刻最多一个 AI 请求，类型为普通聊天或记忆提炼；共用有效连接、按需读取钥匙串、停止、请求代次和退出边界。停止、关闭窗口、成功换肤、清空/重置、睡眠、关闭 AI、退出均取消尚在提炼的任务；晚到分段、解析或完成结果不能发布候选。唤醒不自动提炼。

提炼运行中禁止发送、应用人设、记忆变更、模型/密钥替换和重复提炼。最小化、App 隐藏、桌宠隐藏、安静或专注不取消用户已明确发起的提炼。聊天窗口的现有独立 `chatPresented` 暂停来源继续使用，不借用设置/专注暂停状态；不新增动画轮询、后台提炼计时器或补播。

候选每批绑定角色 ID、皮肤修订、请求代次、提炼时 memoryRevision 与本地来源快照。完成后允许普通聊天继续；历史推进不改变这批来源。成功记忆变更、人设应用、清空/重置、关窗/换肤/退出按前述寿命清除尚未确认的批次。已有完整未保存问答或确认后失败的记忆意图时，先处理保存，避免同角色上下文分叉。

## 8. 组件边界和验证

- PetCore 承担记忆条目/容量、候选结构及来源索引、提示快照、严格解码、v1→v2 显式读取与持久校验。
- 传输适配保持普通聊天合同，复用官方请求/SSE 保护，增加提炼的类型化输入与可注入替身；不引入通用插件/工具系统。
- `ChatArchiveWorker` / FIFO 扩展记忆事务及修订检查；`ChatController` 管理单飞请求、候选寿命、每角色待保存意图和退出汇总。
- `ChatWindowController` 增加记忆入口、纯文字管理与候选确认，复用现有中文输入、模态和状态刷新；是否拆分专用视图文件由实施者决定。Xcode 所有新增源码/测试都显式登记。

验证要求：

1. 模型：20/200 上限、空白/控制字符/NFC/重复 UUID/重复正文、合法空候选、5 条/来源边界和错误整批拒绝；超过 12 轮后记忆仍在提示内，普通请求不包含未确认候选或他角色记忆。
2. 存储：真实 v1 夹具无损读取且不主动改盘，v2 重开；未知/损坏字段保护原字节；人设/追加/裁剪/清空保留记忆；备份重置及写失败；FIFO 和修订冲突，旧回执不恢复清除结果；所有测试用临时配置/假资料。
3. 网络替身：固定请求源与 JSON 输出字段、发送范围、SSE 正常/空/截断/不合法 JSON/来源/重复/超限、状态码/超时/取消/晚到，单次请求且失败不自动重发；密钥不出现在文件或日志。
4. 控制器：提炼/聊天互斥、候选不写盘、明确勾选才保存、确认前修订/身份再检查；普通聊天期间记忆快照不变；关窗/换肤/睡眠/AI 关闭/退出、已确认事务不随网络取消；失败变更跨角色本地重试和退出汇总。
5. 原生优化隔离探针：三套真实皮肤，最小窗口/浅深色/滚动、候选与来源/编辑/满额/失败重试、四个入口页、中文组合输入和模态结束提交；程序化 action 与渲染不记作物理操作或系统焦点通过。
6. 完整原生回归、13 项离线发版、双架构构建/打包、分发核验及 ARM 从 DMG 复制后弹出、中文空格离工程路径独立重开；一次最终独立代码评审。测试数量按实际结果更新。

# 0.1.22 DeepSeek 角色文字聊天设计

日期：2026-10-23（Asia/Shanghai）。基线：`7e87dd5`（0.1.21，主干与资源调查分支已普通同步）。

状态：设计稿已完成自审，等待用户审核书面设计；尚未编写实施计划或产品代码。本轮仅创建本地设计分支 `codex/macos-deepseek-chat`，沿用独立 Mac 仓库原地开发，不另建工作树。推送、标签和 Release 继续需要新的明确指令。

## 1. 用户目标与首版成功标准

用户认为计时窗、统计和备份属于较小提升，选择 D「角色 AI 对话」作为下一条主线；随后指定已有 DeepSeek API，并确认按角色保留最近 12 轮完整对话，重开 App 可续聊。目标是让现有桌宠能够以用户设定的角色口吻连续交流，优先服务自己的 Mac mini M4 日用。

已提出的首版方向包括独立聊天窗、可编辑人设、流式回复、停止与失败重试、复制，以及在 App 中填写并使用 macOS 钥匙串保存密钥。以下窗口布局、默认模型、容量、生命周期和错误处理为拟采用的实现选择，供本次书面审核。

交付目标为 0.1.22 / build23：

1. 从角色右键或菜单栏「聊天…」打开可输入文字的独立窗口，现有单击挥手、双击跳跃继续可用。
2. 使用 DeepSeek 官方 API，默认 `deepseek-flash` 非思考模式；用户可改选 `deepseek-v4-pro`。回复逐步显示，可停止、复制和手动重试。
3. 每个角色可设置背景、性格、说话风格和示例台词；初次使用以当前皮肤名称、介绍作为起点，角色设定可为空，不虚构官方背景。
4. 按清单 `manifest.id` 保存人设与最近 12 轮完整对话。不同 ID 的角色隔离；同一 ID 的多个导入副本共用，与现有个人台词的身份口径一致。
5. 仅在用户发送时联网；请求只含人设、最近完整对话和本次文字。模型只返回文字，不接入工具调用、屏幕内容或系统操作。
6. 现有 schema13、真实旧皮肤、专注规则和全部持久偏好保持原有合同；聊天资料单独保存。arm64 本地可体验，x86_64 保留交叉构建与分发核验。

首版不增加语音、图片/文件输入、搜索、自动长期记忆、AI 台词生成、多服务商配置或中转服务。API 账户由使用者自行配置，App 不附带开发者密钥。原 Windows 仓库与 Minimal Sleep 仅作只读参考。

## 2. 已核对的参考与方案取舍

- 现有 `PetPanel` 不可成为 key/main；`SpeechBubble` 忽略鼠标，只承担临时台词，因此输入使用独立普通 `NSWindow`。
- `StatusBarController` 已长期持有共享设置、专注和更新控制器，适合持有聊天控制器，避免关窗或 SwiftUI 重建导致会话丢失。
- `ReleaseUpdateClient` / `ReleaseUpdateModel` 已有独立 URLSession、取消与代次检查思路；聊天沿用其边界，增加流解析，不把网络任务放进动画调度器。
- 主配置上限 64 KiB；v12 迁移仍解码当前 `PetPreferences`。聊天独立存储可以保持主 schema13 与已有 1–13 读取合同不变。
- 现有设置有七个 Tab，曾因宽度溢出调整窗口；聊天窗口内部提供「对话 / 人设 / 连接」入口，不增加主设置的第八个 Tab。
- Windows 参考副本的 `AI/AiChat.cs` 与 `docs/AI_INTEGRATION.md` 已有四类人设、角色 ID 隔离、最多 12 轮、完整问答成对保存的语义。Mac 采用这些行为设计，用原生 Swift 和钥匙串重新实现，不改动其代码、资源或个人配置。

选择「官方 DeepSeek 直连 + 原生 URLSession」：满足用户已有 API 的条件，无新增 SDK 或依赖。通用多供应商连接器、内嵌 WebView、本机模型服务都会扩大首版范围，本轮不采用。

## 3. 窗口与用户操作

聊天窗采用 AppKit 普通可取焦点窗口，初始约 520×620，最小 440×420，首次居中；本次运行重开保留窗口对象和位置，首版不新增跨重启窗口位置偏好。仅用户打开聊天时激活 App；后台完成、失败、角色切换或唤醒不自动弹出窗口或抢焦点。

「对话」页显示当前角色名称与 ID、可选择和复制的纯文字问答、生成状态、输入框、发送/停止、复制回复及「清空记录…」。输入框支持中文输入法和多行；Enter 换行，Command+Enter 发送，组合输入尚未提交时不发送。不渲染服务端 HTML、Markdown 或自动执行链接。

「人设」页提供背景、性格、说话风格与示例台词。点「应用人设」后保存成功才生效；失败保留编辑草稿和原有效人设。离开人设页、关窗或换角色丢弃未应用的人设编辑，与当前个人台词编辑规则一致。聊天输入草稿另按角色在本次运行内保留。

「连接」页提供 AI 总开关（初始关闭）、两个模型选项、密钥输入/保存与移除，以及明确的保存反馈。基础地址固定为官方 `https://api.deepseek.com`，首版不接受任意中转地址。输入框不回显已保存密钥；成功保存后清空密钥草稿。生成期间禁用密钥替换/移除与模型应用，须先停止；关闭 AI 始终可用并立即取消请求。打开此页、选择模型、开启 AI 或启动 App 均不自动发测试请求；第一次手动发送即可验证连接。

连接页简短说明：发送会将人设、最近 12 轮对话和本次文字交给 DeepSeek，按使用者的 API 账户用量处理。未开启 AI、无密钥、当前角色或连接存档受保护、当前角色存在未处理的保存失败、模态或退出期间禁用发送，并提供对应处理入口。

## 4. 人设、会话与保存合同

人设使用背景 2000、性格 1000、说话风格 1000、示例台词 2000 个 UTF-16 单元的上限；单条用户消息最多 2000，单条完整回复最多 8000 个 UTF-16 单元。允许普通多行文字，拒绝 NUL 等非文字控制内容，空输入不能发送。

系统提示由固定的角色扮演说明和用户保存的人设组成，使用当前皮肤名称，不把用户自定义人设当作官方设定。模型所能看到的范围仅为本次明确提供的内容。

一次发送冻结角色身份、已应用人设、模型、原 12 轮完整历史和输入。请求在应用内单飞；生成中不得再发送，模型和人设的应用暂时禁用，须先停止。客户端把本次用户文字与回复显示为待完成状态，收到正常结束并完成本地保存后，才共同加入正式历史，超过 12 轮按整轮移除最早一轮。

停止、断网、空回复、超长、服务错误、解析错误、非正常结束或流被截断均不加入历史；保留输入供手动重试。已显示的部分回复标记为未完成，可复制，不作为后续上下文。停止或失败不自动重新请求。

生成成功但本地保存失败时，完整结果留在窗口并标记「本次对话尚未保存」；可复制或只重试本地保存，不重新调用 API。完整未保存问答也按 `manifest.id` 持有，关窗、换到其他角色或切到同 ID 副本均不丢失或错配，回到该角色可继续处理。解决前该角色不发送下一条或应用新人设，避免上下文与磁盘状态分叉；其他角色不因此停用。也可明确丢弃本次未保存问答，恢复旧历史并保留输入草稿。退出汇总所有已加载角色的待存结果，而非只看当前窗口。

「清空记录…」确认后取消当前请求，按存储事务顺序原子保存空历史并保留人设；存在完整未保存问答时，确认文案说明成功清空也会丢弃该问答。清空失败保留此前有效历史及尚未保存的完整问答，并显示错误。只清除当前 Mac 的记录，不宣称删除服务商已经收到的数据。删除皮肤不顺带删除聊天资料；重新导入同 ID 可恢复该角色的资料。

## 5. 文件与凭据

聊天存储根为现有 `SettingsStore.url` 同级的 `AI`，因此 `YSGPET_SETTINGS_PATH` 的隔离同时覆盖聊天文件：

```text
AI/
  connection.json
  characters/<角色ID的SHA-256>.json
```

连接文件 v1 只存总开关和模型，上限 8 KiB。角色文件 v1 含原角色 ID、四项人设和最多 24 条交替的 user/assistant 消息，上限 2 MiB。一次只加载当前角色，不启动时遍历全部历史。目录/文件使用仅本用户访问的权限；严格验证版本、重复键、类型、身份、轮次与容量，按同目录临时文件原子替换。

缺失文件使用默认值，只有明确保存人设、连接偏好或完整问答时才落盘。损坏、未知版本或身份不符保留原字节，进入该文件的保护状态，提供经确认的「备份并重置」；不静默覆盖或影响主配置。备份失败不能解除保护。读写放在独立串行任务边界内，不阻塞主线程或每段流式文字写盘。

同一角色的人设应用、完整问答保存、本地保存重试、清空与重置使用有明确事务序号的串行变更队列。完成流的代次与内容在主线程核验后，才可同步登记一次保存意图；登记后属于已接受的文件事务，网络取消不撤回它。后续清空排在此前已接受的问答保存之后，依据当时最新有效状态执行；清空成功后旧回答不能因晚到回调重新出现。事务完成始终更新对应角色的存储状态，当前窗口另检查角色与事务版本，不能用网络代次取代写入顺序。

密钥使用 Security 框架的通用密码项，独立 service/account 标识，只在用户保存、替换、移除或发送时按需访问，不进入 JSON、皮肤、Git、日志或诊断。连接偏好与钥匙串不能形成跨资源原子事务，分别报告实际结果：例如密钥已存但模型偏好未存，不能统称全部成功。

自动化默认使用注入的内存凭据存储，禁止碰正式钥匙串项。确需验证真实 SecItem 时使用单独随机测试标识、明确清理；不读取、覆盖或删除其他凭据。用户日用密钥只通过 App 填写，不要求粘贴到聊天。未得到密钥前，真实 DeepSeek 完整往返标记未测。

## 6. 网络与流处理

使用原生 `URLSession` POST 至固定的 `https://api.deepseek.com/chat/completions`，Bearer 凭据，禁用缓存和 Cookie，拒绝重定向并检查最终来源；不增加 SDK 或依赖。请求包含模型、system/完整对话/current user、`stream: true`、`thinking: {type: disabled}` 与 `max_tokens: 2048`，不传工具或图片字段。

请求体最多 1 MiB；请求闲置超时约 30 秒、总时限约 120 秒，超过后提示可手动重试。DeepSeek 的保活注释仍受总时限限制。成功响应按 SSE 增量解码，处理跨网络分块的 UTF-8、CRLF、空行、注释、data 行、空 choices/用量块和 `data: [DONE]`；单事件/行最多 64 KiB，整个响应最多 1 MiB。

只接收第一个文本回答的 content，不显示或持久化 reasoning 字段；主线程增量发布至多约每 50ms 一次，结束或取消立即提交最后界面状态。只有非空文本、正常 `stop` 与完整结束标志齐备才视为成功。达到长度限制、过滤、工具调用、服务中断、无完成标志的 EOF 等明确显示未完成，不当作完整历史保存。不因 SSE 不支持自动再发一次收费请求。

认证 401、余额 402、限速 429、请求参数 400/422、服务器 500/503 使用本地固定说明；其他状态显示状态码和可重试提示。不把原始响应体、请求头、密钥、人设或聊天内容写入错误日志。所有失败均由用户手动决定是否再次发送，取消不能承诺撤回已经到达服务器的请求。

## 7. 生命周期与桌宠反馈

`ChatController` 在 MainActor 管理状态和请求代次。停止、关闭窗口、成功换肤、确认清空、关闭 AI、系统睡眠、开始退出都会取消当前网络请求并推进代次；之后到达的旧分段或尚未接受的网络结果不能改写窗口或提交档案。已经登记的文件事务继续保存到发送时冻结的角色，不会被取消或挪给新角色；事务结果只更新所属角色的状态，不向新窗口发布旧回复或触发过期反馈。

成功换肤后窗口跟随当前角色，显示其独立人设/历史和本次运行内草稿；同 ID 副本共用存档但仍取消旧请求。换肤失败维持原会话。刷新经状态栏现有回调转发，不覆盖 `PetSession.onStatusChange`，不让每帧或每秒计时刷新触发重载。

隐藏角色、安静模式和专注模式不取消用户主动发送的请求，聊天窗仍可使用。关闭聊天窗取消生成，但保留已保存历史、会话内输入草稿及待处理的完整未保存结果；重开可处理保存，不能自动重发。睡眠取消后唤醒保持停止。

聊天窗可见、未最小化且 App 未隐藏时，用独立的临时 `chatPresented` 状态暂停注视、自动动作、走动和普通互动台词；隐藏、最小化或关闭后解除该来源，其余暂停来源继续有效。不修改原偏好，不借用 `settingsOpen`，避免两个窗口互相关闭暂停。手动点击拖动、专注计时、位置锁定及菜单照常工作。等待回复只在聊天窗显示状态，首版不接管角色为持续“思考”动画。

完整回复成功保存且仍属于本次有效发送的当前角色时，若角色可见、已醒、未安静/专注且没有菜单、设置、鼠标操作、其他手动动作或退出阻挡，可挥手一次；启用原台词开关时再显示至多 80 UTF-16 单元的本地回复摘录，保持字素完整、合并换行并省略超长部分。完整回复保留在聊天窗。后来重试本地保存、已取消或关窗/换肤后的事务完成均不触发回应。不另调用模型生成摘要，不强行显示角色，不抢焦点，不补播被阻挡的反馈。气泡复用既有一次性期限和调度，不新增固定轮询。

开始退出先取消请求，取消退出后不恢复网络请求。等待本次已确认的文件变更完成，再汇总主配置/皮肤清理与聊天保存问题；有完整未保存问答时提供重试本地保存、明确继续退出或取消退出。普通未发送草稿与停止后的部分回复不跨进程保存。最终退出销毁任务、会话、观察者和窗口，不改正式登录项。

## 8. 组件边界

| 组件 | 职责 |
| --- | --- |
| PetCore `ChatProfile` / `ChatConversation` | 文字限制、角色身份、完整问答、12 轮截断、提示词构造 |
| PetCore `ChatStore` / `ChatConnectionStore` | 独立文件、保护状态、备份重置与原子保存，不接触主 schema13 |
| `ChatClient` / SSE 解码器 | 固定官方请求、流解析、大小/超时/结束验证，可注入网络边界 |
| `ChatCredentialStore` | 钥匙串适配与可注入测试替身，提供明确读取/写入/移除结果 |
| `ChatController` | 单飞、角色快照、草稿、取消代次、存档任务、错误与本地保存重试 |
| `ChatWindowController` | AppKit 窗口、中文输入、滚动、复制，呈现对话/人设/连接 |
| `StatusBarController` / `AppDelegate` | 两处聊天入口、共享所有权、皮肤/模态/退出/睡眠协调 |
| `PetSession` 的小型聊天反馈入口 | 独立暂停来源、受门控的一次挥手/短气泡，不执行模型命令 |

保持 Swift 6、macOS14+、系统框架与现有 XCTest。聊天路径不增加动画计时器、不覆盖专注逻辑、不修改真实 JSON/PNG；测试及诊断内容不携带日用密钥或聊天。

## 9. 验证与本地交付

1. 纯逻辑：人设与文字边界、完整轮次、超过 12 轮截断、角色/同 ID 副本隔离、请求快照、提示词包含范围、空输入和超长输出。
2. 文件：v1 往返、重开续聊、损坏/未知版本/重复键保护、身份不符、原子写失败、清空/备份失败、只重试本地保存、旧问答保存与清空的事务顺序、换角色后待存结果保留、不污染主 schema13 或测试配置外目录。
3. 网络替身：请求源与字段、认证不出现在文件/诊断、SSE 分片/UTF-8/保活/空块/完成标志、状态码/超时/断流/过大、取消与晚到结果、无自动第二次请求。离线测试不得伪称真实 DeepSeek 通过。

## 1. 目标与成功标准

为用户自己的 Mac mini M4 提供可日常试用的原生单角色桌宠。继承 Windows 版的真实皮肤、动作语义和故障经验，使用 Swift + AppKit 实现 Mac 客户端。常规设置界面以后按需使用 SwiftUI，首版通过菜单栏完成必要操作。

用户已确定独立仓库、首版功能范围和先本地体验再考虑推送发布的顺序。本设计将这些要求落成可实现、可验证的约定；下述窗口参数、工程结构和保存策略属于实现选择。

首版交付必须具备：

1. 可从 Finder 打开的本地 arm64 `.app`，随附一份未经修改的叶瞬光旧皮肤。
2. 正确的透明待机动画、拖动、单击打招呼、双击跳跃及缺失动作回退。
3. 菜单栏显示、隐藏、召回和完全退出；桌宠不主动抢走其他应用的键盘焦点。
4. 角色位置保存与重启恢复；屏幕布局变化或旧位置失效时恢复可见。
5. 隐藏、系统睡眠和唤醒时调度可控，无逐帧补播或重复计时器。
6. 可复现的构建说明、皮肤兼容矩阵、实际验证记录和已知限制。

后续候选功能为皮肤管理、缩放、自动行为、台词、专注计时、多角色、AI、截图和 OCR；首版不实现这些功能。首版也不增加登录、自启动、网络请求或自动更新。

## 3. 技术与工程选择

采用原生 Swift + AppKit。SwiftUI 可承担后续常规表单，但首版不为尚无需求的设置页引入额外界面。Avalonia 需要额外的 .NET 和界面迁移，纯 SwiftUI 仍需包装桌宠窗口能力，当前没有改变默认路线的证据。

使用原生 Xcode 工程、系统框架和 XCTest，不依赖 XcodeGen、游戏引擎或外部运行库。部署目标设为 macOS 15.0，产物为 arm64；首轮验证仅覆盖实际运行的 macOS 27.0，不能宣称其他系统版本已实测。应用标识使用 `io.github.resker666.yeshunguangpet.macos`。

源码按职责组织为纯逻辑和 Mac 适配两部分，不提前建立大型插件架构：

| 组件 | 职责与边界 |
| --- | --- |
| `SkinLoader` / 皮肤模型 | 读取受限大小 JSON、严格结构检查、字段校验、资源路径与 PNG 校验；返回不可变有效皮肤 |
| `SpritePlayback` | 累计帧期限、当前帧和下次期限、单次动作结束、暂停恢复；接收可注入单调时间，不持有窗口 |
| `PetInteraction` | 点击等待、双击和拖动互斥、动作选择与回退；不直接读屏幕或写配置 |
| `WindowPlacement` | 使用屏幕可用矩形计算位置恢复、限制和召回；纯几何运算可测试 |
| `SettingsStore` | Mac 自己的配置版本与原子保存、无效配置保护；不迁移 Windows 个人数据 |
| `PetPanel` / `PetView` | 原生窗口、图片绘制、鼠标事件和坐标换算 |
| `PetSession` / 应用入口 | 在主线程组合上述组件、菜单栏、生命周期、调度与错误反馈 |

原生对象和会话变更统一在主线程执行。纯逻辑只在测试、替换时确有需要的位置保留时钟或存储边界，不为每个类型创建接口。

## 4. 皮肤加载与兼容合同

默认从应用 `Contents/Resources/Pets/YeShunguang/` 读取真实旧皮肤。实现时提供 `--skin /绝对路径/pet.json` 开发入口，以便检查其他本地皮肤。首版不扫描个人目录，不实现文件选择、ZIP 导入、编辑或更新。

加载失败时给出明确文件与原因，保留菜单栏中的错误状态、召回禁用状态和退出入口；无有效角色时不显示空白宠物窗口。显式指定的无效皮肤不静默切回默认皮肤，以免掩盖兼容错误。

严格遵守参考提交中 `PET_FORMAT.md` 与实际解析代码的字段语义：

- 接受 UTF-8 和可选 BOM，最大 128 KiB；根必须为对象，不接受注释或尾逗号。JSON 嵌套深度上限沿用原解析器的 64 层。
- 在转换为会丢失重复键的字典前检查每层对象键；拒绝重复键，包括原版不区分大小写判定的重复形式。属性名和动作键使用原规范的准确大小写，拒绝未知字段。
- 不直接以 Swift 默认 `Codable` 成功作为完整校验结果。整数、布尔、null、默认值和可选字段分别依照原实现验证；字符串长度上限与原版的 UTF-16 长度语义一致。
- `schemaVersion` 为 1；ID 为小写字母开头的 1–64 位字母、数字或连字符，拒绝 Windows 保留名称。名称、描述、资源名、动作帧与图像上限沿用原约束。
- PNG 最大 64 MiB；解码前检查 PNG 头与 IHDR 尺寸，尺寸须等于格尺寸乘行列数，每边不超过 8192，总像素不超过 16,777,216。随后实际解码，拒绝损坏图像。
- `spriteSheet` 只能是同目录的 PNG 文件名。拒绝 URL、绝对路径、分隔符、Windows 非法文件名字符、目录越界，以及皮肤根目录和文件中的符号链接；检查解析后的实际路径仍在允许的皮肤根内。
- 行列从原图左上角计数，每个动作在同一行连续取帧。每帧 20–10000 ms，帧列表非空且不超出行范围；`idle` 必须存在且循环；`waving`、`jumping`、`failed` 不得循环。

可选字段的兼容范围：

| 字段或能力 | 首版处理 |
| --- | --- |
| 九个既有动作键 | 全部识别和校验；首版按待机、拖动、点击需要使用其中动作 |
| `lookDirections` | 接受省略、空数组或 16 个合法坐标；不执行鼠标注视；null 沿用原版拒绝 |
| `speech` | 接受省略、null 或合法的四类台词数组并执行结构与文本限制校验；不显示台词 |
| `behavior` | 接受省略、null 或合法规则，验证默认值、版本、数量、枚举、权重、冷却、重复条件和动作引用；不执行随机行为 |
| 个人设置与历史 | Mac 使用独立配置；不导入 Windows 设置、密钥或专注历史 |

皮肤文件始终只读；不增加 Mac 专用的 schemaVersion 1 字段，不重写 JSON、重采样或重新生成角色 PNG。兼容矩阵必须区分“读取和校验”与“已执行功能”。

## 5. 透明窗口、绘制与调度

窗口使用无边框、非激活 `NSPanel`，透明背景、`isOpaque = false`、关闭窗口阴影，`hidesOnDeactivate = false`。角色窗口不成为主窗口或键盘窗口；普通显示与拖动不调用激活应用或获取键盘焦点的操作。

窗口尺寸取已加载皮肤的单格尺寸，同值转换为逻辑点；默认叶瞬光为 192×208 逻辑点。原图像素用于裁帧，逻辑点用于窗口定位，backing scale 交给渲染层处理。使用有上下方向标记的独立夹具检查裁剪与绘制方向，避免只凭角色外观猜测。

采用原生图片绘制，缓存已使用的裁剪帧，不为每次重绘重新解码整张 PNG。先保留原图像素和透明度，是否需要其他渲染优化以实际测量决定。

默认窗口层级为 `.floating`，以 `.canJoinAllSpaces` 和 `.fullScreenAuxiliary` 作为跨桌面与全屏场景的初始配置。它们是待验证的配置，不能据此宣称覆盖所有应用、系统界面或 Stage Manager 场景。实测失败时记录可支持场景并调整标准窗口参数，不使用私有 API 或权限绕过。

首版命中范围按完整角色单元格矩形计算，包括格内透明部分；不承诺逐像素鼠标穿透。基础显示、窗口自身拖动与菜单不申请录屏或辅助功能权限。

动画沿用累计帧期限：单调时间决定当前位置，循环动作对总时长取模，单次动作结束后回到 idle。定时器只唤醒下一次必要更新，迟到时直接定位当前帧，不从上次画面逐帧补跑，不引入固定 60 Hz 轮询。计时器必须在拖动的事件跟踪期间仍能更新动画。

隐藏或系统即将睡眠时暂停播放、取消点击等待、停止定时器。只有皮肤有效、角色可见且系统已唤醒时，才恢复保留的播放位置并安排一个后续期限；隐藏期间收到唤醒事件仍保持停止，不自动显示角色。若系统未发送预期睡眠通知，迟到回调仍按累计时间一次定位，不能产生补帧循环。

## 6. 输入与状态约定

输入与菜单按“退出 > 隐藏/睡眠 > 拖动 > 菜单/待判定输入 > 手动动作 > idle”处理。首版没有自动游走或随机动作。

| 输入 | 结果 |
| --- | --- |
| 单击 | 松手后等待系统双击间隔；未收到第二击才播放 waving，缺失则 idle |
| 双击 | 取消等待中的单击；播放 jumping，缺失则 waving，再缺失则 idle |
| 超过 4 逻辑点的拖动 | 取消点击，按按下时的鼠标与窗口偏移移动；水平位移使用 runningRight/Left，缺失则 idle |
| 拖动结束 | 限制到有效显示区域，保存位置并回到 idle；不补发点击 |
| 隐藏、召回、菜单打开、睡眠或输入中断 | 取消待处理点击；结束拖动后无点击反馈，不保留迟到动作回调 |

拖动阈值在任一轴绝对位移超过 4 逻辑点时满足，避免与 backing pixels 混用。系统双击间隔读取 `NSEvent.doubleClickInterval`；第二次按下后若变成拖动，同样不触发单击或双击。

菜单栏始终提供“显示角色/隐藏角色”“召回角色”“退出”。显示/隐藏文案取自实际状态。召回取消当前输入，将角色移到主屏可用区域右下角、距边缘 24 点，显示并播放 waving 或 idle；它不需要激活应用。缺少屏幕或窗口过大时采用可恢复的限制策略，不能写入非有限坐标。

退出先尝试保存最新位置，再停止计时器、取消挂起操作、注销观察者、移除菜单栏项并结束进程。保存失败给出可见错误，允许用户明确选择继续退出；不得反复保存阻止退出。

## 7. 位置保存与错误恢复

配置路径为 `~/Library/Application Support/YeShunguangPet-macOS/settings.json`，使用 Mac 自己的 `schemaVersion: 1`，与皮肤版本含义分开。只保存位置所需的屏幕标识、全局逻辑点原点和该屏幕可用区域快照；窗口大小来自皮肤，不恢复外部输入的任意大小。显示/隐藏状态不跨进程保存，冷启动默认显示角色，方便首次试用和找回。

每次拖动结束、召回、屏幕变化导致位置修正以及正常退出时保存，不在每个鼠标移动事件中写盘。使用同目录临时文件和原子替换；仅在保存成功后更新“已保存”状态。写入失败保留旧文件和运行中的当前位置，显示保存失败及重试入口。

恢复流程：

1. 配置缺失时，将角色放在主屏可用区域右下角。
2. 配置有效、原屏幕存在且布局未变化时恢复保存原点，并确保整个角色矩形位于对应 `visibleFrame` 内。
3. 原屏幕仍在但可用区域变化时，依照旧可用区域中的相对位置映射到新区域，再限制边界；考虑负坐标、菜单栏与 Dock。
4. 原屏幕已移除时召回主屏；收到屏幕参数变化通知时执行相同检查。隐藏角色只更新待恢复位置，不自动显示。
5. 屏幕小于角色时将角色原点限制到能保留最大可见区域的位置；无可用屏幕时保持菜单栏控制与待恢复状态，等待下一次屏幕变化。

配置最大 64 KiB，拒绝未知版本、非有限坐标和无效区域。损坏或未知版本文件保持原样，在安全默认位置启动，并显示恢复提示；本次会话的自动保存不覆盖该文件。用户可从恢复提示明确选择备份旧文件并重置，成功后才恢复保存。原子写入不等于断电持久性保证。

## 8. Minimal Sleep 的复用方式

沿用已安装的 Xcode、Swift 和本地测试工具，不为本任务重新安装完整环境。`SleepTimerPolicy.swift` 的可注入单调时钟、`PlaybackPreferences.swift` 的存储边界、`ImportedSoundStore.swift` 的原子写入与错误反馈可以作为实现参考。

## 10. 实施顺序与风险控制

实施计划应先形成“严格加载真实旧皮肤 → 可见的正确裁帧 → 透明窗口 → 拖动与菜单栏退出”的可运行纵向链路，尽早检验原生窗口风险，再补点击协调、位置保存、召回和恢复。

主要风险及处理：

- **JSON 兼容悄然放宽：** 在解码前检查重复键，并以原规范及参考实现的有效、无效样例验证，明确可选字段已校验但未执行。
- **方向、Retina 和多屏坐标混用：** 像素裁帧与逻辑点定位分开，以方向夹具和实际桌面拖动分别检查。
- **焦点、Spaces、全屏及 Stage Manager 差异：** 首次可见窗口即检查，按实际环境报告限制，不以提高到系统极端窗口层级解决。
- **睡眠、隐藏和迟到任务引发动作积压：** 单一调度所有者、累计期限、取消待处理输入，并测试迟到与恢复。
- **保存失败或旧配置损坏：** 原子替换、保留旧文件、错误可见，未知版本和损坏文件在用户重置前不被覆盖。
- **素材和发布边界混淆：** 原程序 MIT 许可及素材声明分别保留；个人本机使用与公开分发分开记录。

用户已于 2026-10-20 审阅并批准本设计。下一步编写实施计划，供用户审阅并选择执行方式；设计通过不构成推送、打标签或发布授权。
